# 끝에 도달하는 이야기 — 아이디어 설정

텍스트 기반 선택형 게임. 큰 틀은 "80억 분의 1"처럼 선택지가 아주 많고, 선택이 몸과 특성에 따라 달라진다.

## 홈
| 메뉴 | 내용 |
|---|---|
| 게임 시작 | 기본 캐릭터 설정(이름, 성별, 신체, 특성) 후 시작 |
| 이어서 하기 | 저장된 게임 불러오기 (자동 저장 1 + 수동 저장 여러 칸) |
| 사전 | 몬스터·장비·변이 도감. 저장을 단단히 해야 함 (아래 "저장" 참고) |
| 설정 | 저장 · 전투 · 화면 · 소리 · 데이터. 기능은 적당히 |

## 세계관
- 아포칼립스 + 사이버펑크(?)
- **장비**: 무기 / 이식형 무기 / 대체형 무기
- **변이**: 침식 / 감염 / 대체 / 창조 (+ 변이 안 한 상태 = 원본)
- **몬스터**: 고블린·트롤·오크 같은 기본 몬스터에서 시작해 새로운 몬스터를 계속 추가
  - 몬스터를 관리하는 **관리용 사이트**를 따로 만들면 좋음
- **신체** (변이·대체 가능, 부위별 상태를 따로 가짐)
  - 얼굴: 왼눈 / 오른눈 / 코 / 입 / 귀
  - 몸: 가슴(여 캐릭터는 크기) / 성기 / 몸통
  - 팔(왼·오른 따로): 손 / 팔
  - 다리(왼·오른 따로): 발 / 다리

## 전투
- **실시간 턴제**: 타이머가 흐르고, 그 안에 공격 방식을 골라야 한다. 못 고르면 그 사이 공격당한다.
- 주인공이 있으면 주위의 적이 공격할 수 있다 (주변 적 모두가 후보).
- 공격 방식은 장비 종류와 연결: 근접(무기) / 이식형 / 대체형 + 방어·회피·물건
- 신체 상태가 전투에 영향 (예: 다리 변이는 회피, 팔 대체는 대체형 공격)

## 선택과 특성
- 선택지는 신체·특성에 따라 열리거나 잠긴다. (예: 대체한 팔이 있어야 단말기 사용 가능)
- 특성은 캐릭터 설정에서 고르고, 사건에서 늘거나 바뀔 수 있다.

## 정해야 할 것 (열린 질문)
1. "테스트 기반 게임"은 **텍스트 기반**으로 이해했음. 맞는지?
2. 사전·저장: 브라우저 저장소(IndexedDB) + 내보내기/가져오기 파일로 갈지, 서버를 둘지.
   - 브라우저 저장만 쓰면 기기를 바꾸거나 브라우저 데이터를 지울 때 사라짐 → 내보내기 백업을 기본 기능으로.
3. 몬스터/장비 데이터는 JSON 파일로 두고 관리용 사이트가 그 JSON을 편집하는 구조가 단순함.
4. 성별은 여/남/직접 입력으로 시안을 잡았음. 가슴 크기 외에 다른 신체 옵션 범위.
5. 연령 등급 / 성인 표현 수위 (신체 부위에 성기가 포함되므로 표현 방식과 이용 대상을 정해 두는 게 좋음).
